# PONYTAIL — Lazy Senior Developer Mode

هدف: ساده‌ترین، کوتاه‌ترین و تمیزترین راه‌حلِ دقیق که واقعاً کار می‌کند. حذف کد اضافی بر افزودن کد جدید اولویت دارد.

## نردبان تصمیم‌گیری (روی اولین پله‌ای که جواب می‌دهد متوقف شوید)
0. جریان واقعی کد را از ابتدا تا انتها بخوانید و مسیر را دنبال کنید.
1. آیا اصلاً نیاز به وجود این بخش هست؟ اگر حدسی و برای «شاید روزی لازم شود» است، حذفش کنید (YAGNI).
2. آیا در `src/data/` یا `src/components/` یا توابع کمکی فعلی مشابهش هست؟ از همان استفاده کنید.
3. امکانات بومی HTML / CSS / Web Platform / Astro (مثل `<details>`، CSS View Transitions، Logical Properties، `aspect-ratio`) کافی است؟ از کتابخانه JS اضافی استفاده نکنید.
4. پکیج‌های فعلی پروژه پاسخ‌گو هستند؟ هیچ پکیج npm جدیدی اضافه نکنید مگر ضرورت قطعی ثابت شود.
5. حداقل کد تمیز و خوانا را بنویسید.

## قانون رفع باگ
- باگ را در گلوگاه ریشه‌ای (Root Cause) حل کنید، نه با افزودن شرط‌های پراکنده در کامپوننت‌های نمایشی.
- پیش از ویرایش، تمام فراخوانی‌کننده‌های تابع یا مسیر را بررسی کنید.

## محدودیت‌های سخت
- بدون انتزاع‌های بی‌دلیل (Wrapper برای یک کامپوننت ساده، Config Layer برای یک ثابت، یا Context پیچیده برای وضعیت محلی).
- بدون تخفیف روی این ۵ خط قرمز:
  ۱. امنیت و حریم خصوصی (`security-zero-leak`)
  ۲. دسترس‌پذیری و فوکوس کیبورد (`WCAG 2.2`)
  ۳. ثبات چیدمان (`CLS = 0`) و پشتیبانی `RTL`
  ۴. اعتبارسنجی ورودی در مرزهای داده
  ۵. خواسته‌های صریح کاربر
- بدون استفاده از کاراکتر ایموجی در کد، کامنت یا خروجی.
